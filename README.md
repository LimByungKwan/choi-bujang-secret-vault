# BYTE BACK 방어전 2단계 자료실

이 저장소는 1단계에서 만든 자료실의 2단계 구현입니다. 네 건의 가상 메모는 Supabase 학습 테이블로 옮깁니다. 실제 학생 자료, 토큰, 비밀키를 코드나 브라우저 파일에 넣지 마세요.

## 학생이 하는 일: 세 걸음

1. GitHub 계정을 만듭니다.
2. 방어전 카드의 **Deploy** 버튼을 누릅니다. Vercel에 GitHub로 로그인하고 저장소를 선택해 Deploy를 누릅니다.
3. 배포가 끝나면 화면에 나온 `https://…vercel.app` 주소를 현재 단계 카드에 제출합니다. 저장소 주소나 설정 파일은 적지 않습니다.

배포가 끝나면 `/` 화면은 Vercel 함수 `/api/notes`를 통해 Supabase `learning_notes` 테이블의 메모를 불러옵니다. `public/data.json`은 빌드에서 제거되며 더 이상 생성되지 않습니다.

**현재 단계의 알려진 약점:** `/api/notes` 주소는 인터넷에서 누구나 호출할 수 있고 로그인·소유자 검사를 하지 않습니다. 함수는 서버 전용 `SUPABASE_SECRET_KEY`로 데이터베이스에 접근하므로, 이 키가 브라우저 파일이나 응답에 들어가지는 않지만 함수의 응답으로 메모 네 건은 누구에게나 공개됩니다. 다음 단계에서 이 함수에 인증과 접근 제어를 추가해야 합니다.

## 가상 메모 잔존 확인

다음 문장 네 개를 각각 정확한 문구로 검색하세요.

- `실습용 가상 과제 기록`
- `실습용 가상 포트폴리오 기록`
- `실습용 가상 리추얼 기록`
- `실습용 가상 행정 기록`

GitHub에서는 저장소의 **Code** 검색에서 기본 브랜치의 최신 파일을 대상으로 위 문장들을 하나씩 검색하세요. 현재 구성이라면 검색 결과는 이 확인 절차가 있는 README와 `supabase/migrations/`의 SQL에만 있어야 합니다. `data.json`은 빈 목록이고 `public/data.json`은 없어야 합니다.

Vercel에서는 **Deployments**에서 현재 Production 배포를 열고, 배포 주소의 `/`와 `/aleph.json` 등 정적 파일 내용에서 같은 문장을 검색하세요. 여기서는 문장이 나오지 않아야 하며 `/data.json`은 404여야 합니다. 반면 `/api/notes`를 GET으로 호출하면 지금은 네 문장이 반환됩니다. 이 함수가 공개되어 있다는 현재 약점의 확인 결과이지, 메모가 숨겨졌거나 키가 노출됐다는 뜻은 아닙니다.

이 절차는 GitHub 최신 파일과 현재 배포만 확인합니다. 옛 공개 커밋이나 이전 배포가 남아 있는 동안에는 과거 노출이 해소됐다고 쓰지 마세요. 과거 커밋과 이전 배포 주소도 별도로 확인하고, 남아 있다면 과거 노출은 계속된 것으로 취급해야 합니다.

## 시작 틀의 자동 처리

`vercel.json`은 정적 결과물 `public`과 `api/`의 서버 함수를 배포합니다. `npm run build`는 1단계 이후 설정에서도 동작하며, Vercel이 제공하는 저장소 소유자·이름, 커밋 SHA, 배포 URL을 검증해 `public/aleph.json`을 계속 생성합니다. 검증 정보가 없으면 빌드가 실패하므로 빈 주소를 내보내지 않습니다. `aleph.json`만으로 저장소 소유권이나 방어 성공을 인정하지 않습니다.

Vercel 프로젝트의 **Settings → Environment Variables**에 `SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 설정하세요. 실제 값을 저장소, 브라우저 코드, API 응답, 로그에 기록하지 마세요. `SUPABASE_SECRET_KEY`는 서버 함수에서만 사용합니다.

로컬 정적 빌드는 `npm run build -- --local`로 확인할 수 있습니다. 이 명령은 `/aleph.json`을 만들지 않으며, Vercel 서버 함수 실행이나 배포를 증명하지 않습니다. `src/attack-check.mjs`의 비로그인 `/api/notes` 요청은 학생의 자기 점검이며 심판 판정이 아닙니다.

## 다음 단계의 코딩 도구에 전달할 규칙

[AGENTS.md](AGENTS.md)를 먼저 읽히고 한 번에 한 제작 단위만 요청하세요. 다음 단계에서는 자료 API에 인증과 소유자별 접근 제어를 추가해야 합니다. 3단계 이후의 로그인, 허용 경로, 5단계의 원본 API 주소, 6단계 이후 정책 규칙은 해당 단계 원고와 계약에 맞춰 추가합니다. 비밀번호·토큰·서버 전용 키·실제 학생 기록을 코드, Git, 제출 묶음에 넣지 않습니다.

`src/decider.mjs`와 `src/detect.mjs`의 로컬 시험은 반 엔진이나 운영 심판의 결과가 아닙니다. 1단계 이후 제출 묶음 계약 `aleph.defense.submission.v2`는 `scripts/bundle.mjs`에 남아 있으며, 코딩 도구가 해당 단계의 최신 배포 주소와 Git 원격을 맞춘 뒤 사용합니다.
